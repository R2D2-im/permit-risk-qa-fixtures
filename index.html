5. SEC-001 金额编码与 schema 干扰

这些请求刻意保留 JSON 中的原始类型和值。请检查页面底部证据，不能只看钱包格式化后的 token 金额。

非零金额的不同编码 · 4 cases
仅签名

S01 · ERC-2612 hex 非零

value: "0x1"。必须继续识别授权；EOA 提醒、黑名单阻断均不能消失。

仅签名

S02 · PermitSingle JSON number

amount: 1，是 number 而非 string。必须继续识别授权。

仅签名

S03 · Batch ["0", "0x1"]

第二项 hex 非零；不得因第一项为零而按整批撤销。

仅签名

S04 · Batch ["0", 1]

第二项为 JSON number；不得漏掉第二项授权风险。

6. SEC-002 无 0x 前缀 spender

这些请求会从当前选择的 spender 去掉 0x 后再发送。请在复制的 JSON 中确认 message.spender 恰好为 40 位 hex 且没有前缀；Preview 中的风险目标仍应是同一个规范地址。
